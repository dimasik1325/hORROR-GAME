# МОДУЛЬ 1: АРХИТЕКТУРА ДАННЫХ И СЮЖЕТНЫЙ ЯКОРЬ

## 1.1. Логика Сюжета и Нарративная Драматургия

Сюжет игры построен по классической трехактной структуре с деконструкцией архетипа ненадежного рассказчика (Unreliable Narrator) и психологическим твистом в финале.

```
+-----------------------------------------------------------------------------------+
|                                  АКТ I                                            |
|                          "ПРИГЛАШЕНИЕ В ТУМАН"                                    |
|   Прибытие на кордон -> Расследование пропажи геодезистов -> Первые аномалии      |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                                  АКТ II                                           |
|                           "АНАТОМИЯ РАСПАДА"                                      |
|   Психоз -> Встреча со Сплетенным -> Находка дневников со своим почерком          |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                                  АКТ III                                          |
|                          "ОТРЕЧЕНИЕ И УРОБОРОС"                                   |
|   Алтарь Первородной Коры -> Раскрытие: Уэйн — Нулевой Пациент -> Замыкание цикла |
+-----------------------------------------------------------------------------------+
```

### АКТ I: «Приглашение в туман» (Экспозиция и Инцидент)
* **Протагонист:** Детектив Уэйн, бывший следователь убойного отдела, страдающий провалами в памяти после трагической гибели напарника.
* **Сеттинг:** Урочище "Черный Омут" — глухой массив восточносибирской тайги, отрезанный от цивилизации заболоченными реками.
* **Завязка:** Уэйн прибывает на заброшенный кордон лесничества по анонимному письму с просьбой расследовать исчезновение экспедиции геодезистов и деятельность тайной секты «Адепты Первородной Коры».
* **Геймплейный фокус:** Ознакомление с механикой ориентирования, управление батареей фонарика, подбор первых заметок.
* **Хоррор-триггер:** Постепенное разрушение евклидовой геометрии: деревья за спиной меняют положение; компас начинает указывать на ближайшие ритуальные тотемы; в радиоприемнике сквозь белый шум пробивается зацикленный шепот.

### АКТ II: «Анатомия распада» (Развитие конфликта и прогрессия безумия)
* **Развитие:** Уэйн углубляется в чащу, следуя за ориентирами культа. Лес начинает активно сопротивляться его присутствию.
* **Антагонист:** Появляется «Сплетенный» (The Weaver) — антропоморфная гротескная сущность из скрученных корней, костей и плоти. Чудовище не просто выслеживает детектива, а реагирует на уровень его паники.
* **Психологический слом:** Уэйн находит стоянку геодезистов, превращенную в место жертвоприношения. Среди вещей он обнаруживает:
  1. *Дневник Нулевого Пациента*, написанный его собственным почерком и содержащий точные детали его биографии.
  2. *Бобинный магнитофон*, на котором записан его собственный голос, хладнокровно отдающий приказ геодезистам войти в топь и принести себя в жертву Древу.
* **Диссоциация:** Рассудок Уэйна катастрофически падает. Игрок видит галлюцинации: повешенные на соснах тела принимают облик самого Уэйна.

### АКТ III: «Отречение и Уроборос» (Кульминация и Твист)
* **Кульминация:** Уэйн пробивается к эпицентру аномалии — исполинской «Лиственнице Первородной Коры», чьи корни оплели древнее капище.
* **Шокирующее откровение:** Уэйн — не спасатель и не сторонний детектив. Он является основателем, верховным жрецом и **«Нулевым Пациентом»** культа. Поняв, что ритуал слияния с Древом требует абсолютной чистоты и первобытного страха, Уэйн сам стер себе память с помощью психоактивных спор и ритуального надреза лобной доли. Он сам отправил себе фальшивое письмо с фальшивым расследованием, чтобы пройти путь жертвы с чистым, незамутненным сознанием.
* **Финал (Интерактивная дилемма):**
  * *Принятие Корней:* Уэйн вонзает ритуальный нож в сердце, завершая ритуал и растворяясь в биомассе Леса (расширение зоны тумана).
  * *Вечный Уроборос:* Уэйн в панике проводит ритуал стирания памяти заново, просыпается на кордоне с письмом в руке и снова шепчет: *"Я должен найти пропавших..."*. Цикл распада перезапускается.

## 1.2. Архитектура Ресурсов (Resource-Driven Design)

В архитектуре Godot 4.6 кастомные ресурсы (`@tool Resource`) отделяют данные от логики рендеринга, поддерживают горячую перезагрузку и строгую валидацию в инспекторе.

```
                +-------------------------+
                |        Resource         |
                +------------+------------+
                             |
              +--------------+--------------+
              |                             |
    +---------v---------+         +---------v---------+
    |     ItemData      |         |    SanityEvent    |
    |  (Предметы/Лут)   |         | (Триггеры Психоза)|
    +-------------------+         +-------------------+
```

### 1. `ItemData.gd`
Отвечает за все предметы в игре: батарейки, аптечки, записки, ключи, ритуальные артефакты. Содержит метаданные, физические параметры (вес для стамины), звуки и логику применения (`use()`).

### 2. `SanityEvent.gd`
Модульный дескриптор психотических событий: тип галлюцинации (шепот, спавн фантома, сбой света, искажение пространства), порог рассудка, 3D-позиционирование за спиной игрока и кривые интенсивности шейдеров.

# МОДУЛЬ 4: МНОГОПОТОЧНЫЙ СТРИМИНГ МИРА (CHUNK-BASED WORLD STREAMER)

## 4.1. Архитектура `WorldStreamer.gd`

1. **Координатная сетка:** Мир разбит на чанки $64 \times 64$ метра в плоскости $XZ$.
2. **Асинхронная загрузка:** Использование `ResourceLoader.load_threaded_request()` в фоновых потоках Godot 4.6.
3. **Бюджетирование кадра:** Ограничение инстанцирования (максимум 2 чанка за кадр) для исключения просадок времени кадра (Frame Spikes).
4. **Гистерезис колец:** `load_radius = 2`, `unload_radius = 3`. Разница в 1 чанк исключает постоянную перезагрузку при колебаниях игрока на границе чанка.

## 4.2. Смена слоев Безумия (Visual Layers)

* При `current_sanity < 40.0%` срабатывает событие смены слоя.
* Скрытые хоррор-объекты (повешенные куклы, кровавые тотемы, ложные коллизии) имеют тег `sanity_horror_prop` и привязаны к `Layer 2`.
* Деревья на лету получают команду в `ShaderMaterial` активировать параметр `insanity_bleed_intensity`, трансформируя нормальную текстуру коры в пульсирующую плоть.

# МОДУЛЬ 5: ТЕХНИЧЕСКИЙ ШЕЙДЕР И ЭФФЕКТЫ ХОРРОРА

Файл: `shaders/sanity_postprocess.gdshader`

### Математический аппарат шейдера:
1. **VHS Jitter & Scanlines:**  
   $$\text{Scanline} = \sin(\text{uv.y} \cdot \text{density} + 4t) \cdot 0.5 + 0.5$$
2. **Пульсация Сердцебиения (Lub-Dub Curve):**  
   $$H(t) = \left(e^{-28\tau_1} \sin(35\tau_1) + 0.7 e^{-32\tau_2} \sin(35\tau_2)\right) \cdot \text{Sanity}$$
3. **Дисторсия линзы (Barrel Distortion):**  
   $$\vec{r}' = \vec{r} \cdot (1.0 + k \cdot \|\vec{r}\|^2)$$
4. **Радиальная Хроматическая Аберрация:**  
   Смещение каналов $\text{UV}_R$ и $\text{UV}_B$ пропорционально квадрату расстояния от центра экрана и текущему уровню безумия.

## 6.2. Методы оптимизации для Godot 4.6 (Taiga Forest Optimization)

```
                       +-------------------------------------------------+
                       |             ОПТИМИЗАЦИЯ ГОДОТ 4.6               |
                       +------------------------+------------------------+
                                                |
         +--------------------+-----------------+--------------------+
         |                    |                                      |
+--------v--------+  +--------v--------+                    +--------v--------+
| Occlusion       |  | MultiMesh       |                    | Dynamic NavMesh |
| Culling         |  | Foliage / Grass |                    | Baking (Thread) |
| (Стволы/Холмы)  |  | (GPU Frustum)   |                    | (WorkerPool)    |
+-----------------+  +-----------------+                    +-----------------+
```

### 1. Occlusion Culling для густого леса
* В густом лесу миллионы полигонов деревьев перекрывают друг друга. 
* Используется узел `OccluderInstance3D` с запеченными упрощенными цилиндрическими мешами для стволов деревьев (Bake Occluder) и низкополигональными картами высот рельефа.
* Включается `RenderingServer.bake_render_occlusion()`, отсекающий до 70% геометрии вне прямой видимости камеры.

### 2. Оптимизация прорисовки подлеска через `MultiMeshInstance3D`
* Трава, папоротники и хвоя инстанцируются не отдельными нодами `MeshInstance3D`, а через батчинг `MultiMeshInstance3D` (до 50 000 травинок на вызов отрисовки — 1 Draw Call на чанк).
* Настройка `material_override`:
  * Включение `Distance Fade` (Pixel Alpha / Dither) с 25 до 45 метров.
  * Frustum Culling на уровне GPU-инстансов.
  * Отключение теней для мелких травинок (`cast_shadow = SHADOW_CASTING_SETTING_OFF`), сохраняя тени только для деревьев.

### 3. Запекание навигационных сеток в рантайме (Runtime NavMesh Baking)
* При стриминге чанков статический запеченный NavMesh не подходит для бесконечного леса.
* При загрузке группы чанков вызывается метод:
  ```gdscript
  NavigationServer3D.bake_from_source_geometry_data_async(
      navigation_mesh, 
      source_geometry_data, 
      _on_navmesh_bake_completed
  )
  ```
* Фоновый поток строит навигационные полигоны без зависания рендера, сшивая края чанков через `NavigationRegion3D.bake_navigation_mesh()`.

### 4. Профилирование потоков и ресурсов через Engine Monitor API
* Интеграция телеметрии в реальном времени:
  ```gdscript
  var static_mem: float = Performance.get_monitor(Performance.MEMORY_STATIC) / (1024.0 * 1024.0)
  var draw_calls: float = Performance.get_monitor(Performance.RENDER_TOTAL_DRAW_CALLS_IN_FRAME)
  var active_threads: float = WorkerThreadPool.get_caller_task_id()
  ```
* Контроль бюджетов:
  * **Draw Calls:** $\le 850$ на кадр в густом лесу.
  * **Frame Time (Physics Process):** $\le 3.5$ мс.
  * **VRAM Usage:** $\le 3.2$ ГБ для текстур и буферов тумана.
